# Бот записи на занятия — ЮKassa / СБП

По умолчанию (все значения `PAYMENT_FLOW`, кроме `telegram`, включая прежнее `sbp`) клиент выбирает один из двух способов:

- «Оплатить картой» — защищённая платёжная страница ЮKassa для ввода карты.
- «Оплатить через СБП» — страница выбора банка с переходом в его приложение; на компьютере QR-код.

Оба способа используют одни shopId и секретный ключ. СБП должен быть отдельно доступен в магазине ЮKassa. Если сервис отклонил создание платежа СБП, клиент может сразу выбрать карту. По одной заявке допускается только один активный платёж: пока он не завершён/отменён, повторный выбор возвращает существующую ссылку. Это защищает от двойной оплаты.

Общий прайс всех направлений хранится в `pricing.js`. После выбора дня клиент выбирает тариф: пробное 900 ₽, разовое 1 100 ₽, 4 занятия 4 000 ₽, 6 — 5 500 ₽, 8 — 6 500 ₽, 10 — 7 500 ₽, 12 — 8 500 ₽, безлимит на месяц — 15 000 ₽. Команда `/prices` показывает прайс. Один визит — 60 минут. Название, цена и условия тарифа сохраняются в заявке; в платёж и чек передаётся полная цена выбранного тарифа. Старые заявки не пересчитываются. Все абонементы действуют один месяц с момента активации. Автоматическая активация, списание посещений и контроль срока пока не реализованы; их ведёт администратор. Правила допуска к пробному и посещения нескольких направлений не заданы этим прайсом и автоматически не ограничиваются. Бот проверяет статус через API ЮKassa каждые 15 секунд (при большом числе заявок обход может занять дольше), также есть кнопка «Проверить оплату». Возврат в Telegram и кнопка «Я оплатил» не подтверждают получение денег.

## Включение

1. Подключите СБП в магазине ЮKassa. Возьмите shopId и секретный API-ключ в личном кабинете. Это не платёжный токен BotFather.
2. В существующий `.env` добавьте `PAYMENT_FLOW=sbp`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_RETURN_URL=https://t.me/имя_вашего_бота`. Не перезаписывайте имеющиеся TELEGRAM_TOKEN и ADMIN_ID. Образец: `.env.example`.
3. Если чеки формирует ЮKassa, установите `YOOKASSA_RECEIPT_ENABLED=true`, задайте `YOOKASSA_VAT_CODE` и `YOOKASSA_PAYMENT_MODE` по настройкам магазина. `full_prepayment` означает полную предоплату. НДС автоматически не выбирается. Для чека СБП используется телефон, указанный при записи; для встроенного Telegram-счёта запрашивается email. При `false` данные чека не передаются — требуется подходящая для магазина отдельная схема фискализации.
4. Node.js 18 или новее, `npm ci`, `npm test`, затем `npm start` из каталога проекта. Один экземпляр процесса: файловая база не предназначена для нескольких параллельных ботов.
5. Сначала используйте тестовый магазин и его ключи. Проверьте создание ссылки, успешную оплату, отмену, сумму, чек, статус заявки, уведомления. Тестовый магазин имитирует банк; реальное открытие банковского приложения нужно проверить отдельно на телефоне после включения рабочего магазина.

Для этого сценария отдельный HTTPS-сервер не нужен: бот сам проверяет платежи по API. Нужен исходящий доступ к api.yookassa.ru и Telegram. Автопроверка работает, пока запущен бот, и возобновляется после перезапуска.

## Повторные попытки и хранение

- `/payments` в личном чате повторно выдаёт оплату по неоплаченным заявкам. Пока платёж активен, используется прежняя ссылка. После подтверждённого `canceled` можно создать новый платёж.
- Место резервируется перед созданием платежа и освобождается после подтверждённой отмены ЮKassa. Простое истечение локального таймера не снимает резерв. При СБП срок оплаты у ЮKassa — 1 час.
- При сбое связи сохраняются тело запроса и ключ идемпотентности, чтобы не создать второй платёж. Неопределённый POST старше 23 часов не повторяется автоматически (срок ключа ЮKassa — 24 часа). Администратор находит платёж в кабинете и выполняет `/sbp_reconcile ID_заявки ID_платежа_ЮKassa`. Бот проверит сумму, магазин и привязку заявки по API. Если платёж в кабинете отсутствует, нужна ручная техническая сверка; вслепую резерв не удаляйте.
- `data/orders.json` хранит идентификатор платежа, статус и отметки уведомлений. Уведомления, которые не удалось отправить, повторяются. При сбое между отправкой и сохранением возможен повтор уведомления, но не списания.
- Изменение/отмена записи администратором не отменяет платёж и не возвращает деньги. Если деньги пришли после изменения статуса, бот фиксирует оплату и просит администратора сверить запись. Возвраты выполняются через кабинет ЮKassa.
- Сохраняйте `data` и `sessions.json` между обновлениями контейнера и делайте резервные копии.

## Прежний вариант: встроенный счёт Telegram

Для него укажите `PAYMENT_FLOW=telegram` и `YOOKASSA_PROVIDER_TOKEN`, полученный в BotFather → ваш бот → Payments → ЮKassa. Новые заявки будут получать встроенный счёт. Уже созданные платежи СБП продолжают обслуживаться по API, поэтому ключи магазина не удаляйте до их завершения. Старые Telegram-счета заявки отключаются при её переводе на СБП; начатую оплату Telegram сначала нужно завершить/сверить.

Для зависшего встроенного платежа Telegram администратор сначала проверяет, что деньги не списаны и платёж не обрабатывается, затем выполняет `/payment_release ID CONFIRM`. Эта команда не применяется к СБП.

## Проверка

`npm test` — проверки с имитацией API: цена, реквизиты, идемпотентность, последнее место, восстановление после сбоя, отмена и ошибки сохранения. Реальные деньги не списываются. Прогон тестов не заменяет проверку вашего магазина.
