Telegram-бот для танцевальной школы: помогает выбрать направление, записаться на удобный день, приобрести занятие или абонемент и оплатить его через ЮKassa. Администратор получает уведомления, просматривает заявки и управляет их статусами в чате.

## ✨ Возможности

| Для клиента | Для администратора |
| --- | --- |
| Каталог детских и взрослых групп | Уведомления о новых заявках и платежах |
| Расписание, описание и уровень направления | Просмотр заявок и истории изменений |
| Выбор дня и тарифа | Подтверждение, перенос и отмена записи |
| Оплата картой или через СБП | Отметки о посещении и завершении |
| Повторное получение ссылки на оплату | Статистика и занятость групп |
| Вопрос администратору прямо в боте | Ответы клиентам и экспорт заявок |

## 🧭 Как проходит запись

**Категория → направление → имя → телефон → день → тариф → подтверждение → способ оплаты**

- **Банковская карта:** клиент открывает защищённую форму ЮKassa и вводит данные карты на стороне платёжного сервиса.
- **СБП:** клиент выбирает банк и подтверждает платёж в его приложении. На компьютере платёжная страница показывает QR-код.
- После подтверждения оплаты бот обновляет заявку и уведомляет клиента и администратора.

Сумма берётся из выбранного тарифа. Название, стоимость и условия сохраняются в заявке: последующее изменение прайса не пересчитывает ранее созданные заказы.

## 🚀 Быстрый старт

Потребуются **Node.js 18+**, npm, токен Telegram-бота и магазин ЮKassa. Выполняйте команды из папки проекта.

```bash
npm ci
```

При первой настройке создайте `.env` по образцу:

```bash
cp .env.example .env
```

Если `.env` уже существует, дополните его вручную, сохранив текущие значения.

```dotenv
TELEGRAM_TOKEN=токен_бота
ADMIN_ID=telegram_id_администратора

PAYMENT_FLOW=sbp
YOOKASSA_SHOP_ID=идентификатор_магазина
YOOKASSA_SECRET_KEY=секретный_ключ_магазина
YOOKASSA_RETURN_URL=https://t.me/your_bot

YOOKASSA_RECEIPT_ENABLED=false
YOOKASSA_VAT_CODE=
YOOKASSA_PAYMENT_MODE=
```

`PAYMENT_FLOW=sbp` сохраняет совместимость с прежней настройкой и включает **оба способа: карту и СБП**. Значение `telegram` включает альтернативный сценарий встроенных счетов Telegram.

```bash
npm test
npm start
```

Бот работает через Telegram polling. Отдельный публичный HTTPS-сервер для приёма уведомлений не требуется; нужен исходящий доступ к Telegram и API ЮKassa.

## ⚙️ Настройки

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_TOKEN` | Токен бота из BotFather |
| `ADMIN_ID` | Telegram ID администратора; свой ID можно узнать командой `/id` |
| `PAYMENT_FLOW` | `sbp` — выбор карты или СБП; `telegram` — встроенный счёт |
| `YOOKASSA_SHOP_ID` | Идентификатор магазина |
| `YOOKASSA_SECRET_KEY` | Секретный ключ: кабинет ЮKassa → Интеграция → Ключи API |
| `YOOKASSA_RETURN_URL` | HTTPS-ссылка для возврата, например ссылка на бота |
| `YOOKASSA_RECEIPT_ENABLED` | `true` — передавать данные чека в ЮKassa |
| `YOOKASSA_VAT_CODE` | Код НДС для позиции чека |
| `YOOKASSA_PAYMENT_MODE` | Способ расчёта для чека, например `full_prepayment` |
| `YOOKASSA_PROVIDER_TOKEN` | Только для встроенных счетов: платёжный токен BotFather |

### Подключение магазина и чеков

ShopId и секретный ключ должны относиться к одному магазину. Карта и СБП должны быть доступны в его настройках. Если ЮKassa отвечает `Payment method is not available`, выбранный способ не подключён; клиент может выбрать другой после отклонения запроса.

Для чеков включите `YOOKASSA_RECEIPT_ENABLED=true` и заполните НДС и способ расчёта согласно настройкам магазина. В сценарии оплаты по ссылке используется телефон из заявки; встроенный Telegram-счёт запрашивает email. При `false` данные чека не отправляются — для магазина должна быть предусмотрена подходящая отдельная схема фискализации.

Сначала проверьте сценарий на тестовом магазине. Тестовый платёж не подтверждает работу перехода в реальное банковское приложение: это проверяется отдельно после подключения рабочего магазина.

<details>
<summary><strong>Альтернативный сценарий: встроенный счёт Telegram</strong></summary>

В BotFather откройте `/mybots` → ваш бот → Payments → ЮKassa. Полученный платёжный токен задайте как `YOOKASSA_PROVIDER_TOKEN`, а `PAYMENT_FLOW` — как `telegram`.

Новые заявки будут получать встроенные счета. Уже созданные платежи по ссылкам продолжают проверяться через API — не удаляйте ключи магазина до их завершения. Начатую оплату Telegram необходимо завершить или сверить перед переходом этой заявки на оплату по ссылке.

</details>

| Команда | Действие |
| --- | --- |
| `/start` | Открыть меню и начать запись |
| `/prices` | Посмотреть все тарифы |
| `/payments` | Выбрать оплату по неоплаченным заявкам |
| `/id` | Узнать свой Telegram ID |

## 👑 Команды администратора

Доступ определяется значением `ADMIN_ID`.

| Команда | Действие |
| --- | --- |
| `/adminhelp` | Справка по управлению |
| `/stats` | Статистика заявок и расчёт выручки по их статусам |
| `/seats` | Занятость групп |
| `/orders` | Список заявок: первые 10 записей |
| `/orders pending` | Заявки, ожидающие оплаты |
| `/orders paid` | Заявки со статусом «Оплачено» |
| `/order 2` | Детали заявки №2 и последние изменения |
| `/status 2 confirmed` | Изменить статус заявки |
| `/reschedule 2 20.10 18:00 причина` | Перенести запись |
| `/noshow 2 причина` | Отметить неявку |
| `/export` | Выгрузить все заявки в файл |

Статусы заявок: `pending`, `paid`, `confirmed`, `cancelled`, `completed`, `rescheduled`, `no_show`.

> Статус заявки может быть изменён вручную. Поэтому `/stats` и `/orders paid` не заменяют финансовый отчёт ЮKassa. Отмена записи в боте не выполняет возврат денег — возврат оформляется отдельно через ЮKassa.

## 💳 Особенности платежей

- **Подтверждение от сервиса.** Возврат в бот и кнопка «Я оплатил» не являются доказательством оплаты.
- **Проверка реквизитов.** Сверяются сумма, валюта, магазин и принадлежность заявки; для Telegram-счёта — также плательщик.
- **Один активный платёж.** Повторное нажатие возвращает прежнюю ссылку. Пока платёж активен, второй способ не создаёт параллельное списание.
- **Резерв места.** Место резервируется на время платежа. После подтверждённой отмены или отказа в создании резерв освобождается.
- **Восстановление после сбоя.** Запрос и ключ идемпотентности сохраняются на диске. Повторный запрос использует тот же ключ.
- **Автопроверка.** Статусы проверяются с интервалом 15 секунд; при большом числе заявок обход может занимать дольше. После перезапуска проверка продолжается.
- **Обработка ошибок.** В журнал выводится причина отказа ЮKassa; отклонённые запросы HTTP 400 не повторяются бесконечно.

<details>
<summary><strong>Сверка зависшего платежа</strong></summary>

Если результат создания платежа неизвестен, запрос старше 23 часов не повторяется автоматически: срок хранения ключа идемпотентности ЮKassa ограничен. Найдите платёж в кабинете и выполните:

```text
/sbp_reconcile ID_заявки ID_платежа_ЮKassa
```

Несмотря на название, команда применяется к оплате по ссылке как картой, так и СБП. Бот проверяет реквизиты через API. Если платёж не найден в кабинете, требуется техническая сверка; не удаляйте резерв вслепую.

Для незавершённого **встроенного платежа Telegram**, после проверки отсутствия списания и обработки, предусмотрена команда:

```text
/payment_release ID CONFIRM
```

Она не применяется к платежам по ссылке.

</details>

## 🧪 Тестирование и эксплуатация

```bash
npm test
```

Тесты используют имитацию API и проверяют тарифы, суммы, реквизиты, последнее место, повторные события, выбор способа оплаты, ошибки хранения и восстановление после сетевого сбоя. Они не списывают деньги и не заменяют проверку интеграции с вашим магазином.

Запускайте **один экземпляр бота**: файловое хранилище не рассчитано на несколько процессов. Сохраняйте `data/` и `sessions.json` между обновлениями и делайте резервные копии. Файлы сессий и заявок исключены из Git, но остаются на сервере. Неотправленные уведомления по API-платежам повторяются; при сбое между отправкой и сохранением отметки возможно повторное уведомление.
